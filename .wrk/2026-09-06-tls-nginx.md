### DNS API integration (2026-09-06)

- Supplied `.cfg/DNS.txt` transferred over SSH to `/etc/letsencrypt/sensecms/DNS.txt` (root:root 0600; parent directory 0700). Not tracked in Git or reachable through the webroot.
- Hook source: `deploy/certbot/ispconfig-dns.py`; installed under `/usr/local/lib/sensecms-certbot/`. Uses Python's standard library and existing `dig`, no new packages.
- HTTPS API endpoint: `https://mas.ittsp.net:333/remote/json.php`; certificate verification stays enabled and redirects are refused.
- Scope guard: zone 117, server 3, owner sys_userid/sys_groupid 10, client 9, exact `_acme-challenge.sensecms.com.` name, TXT type and exact challenge value. Client 9 was confirmed read-only in ISPConfig; Client API functions are not required. Zone ownership changes intentionally fail closed.
- Hook scope does not imply server-enforced API account isolation. No extra account privileges were granted by this implementation.
- ISPConfig required nonempty `stamp` and `serial` fields; the first staging attempt failed on an empty datetime. Added both fields and regression assertions.
- Propagation checks use both authoritative servers (10-minute timeout) plus a 65-second positive-cache grace period. Independent public resolvers can retain old negative answers for up to the zone's negative-cache TTL; they are not used as a gate for ACME validation.
- Cleanup deletes only records matching the exact zone, name, type and current validation token. Existing inactive manual records and unrelated records remain untouched.
- Eight isolated unit tests cover scope guards, selective/idempotent cleanup, propagation failures and failure cleanup. Deployment hook validates Nginx before reload and only runs for the Sense CMS lineage.
- Previous renewal configuration backup: `/root/sensecms-backups/sensecms.com.renewal-pre-dns-api.conf`.
- Configure with `certbot reconfigure --non-interactive --cert-name sensecms.com --manual-auth-hook '/usr/local/lib/sensecms-certbot/ispconfig-dns.py auth' --manual-cleanup-hook '/usr/local/lib/sensecms-certbot/ispconfig-dns.py cleanup' --deploy-hook /usr/local/lib/sensecms-certbot/reload-nginx.sh --run-deploy-hooks`. This saves settings only after successful staging validation.
- Subsequent verification: `certbot renew --cert-name sensecms.com --dry-run --run-deploy-hooks --no-random-sleep-on-renew`. For rollback, restore only the saved renewal configuration; this returns renewal to manual mode without replacing the active certificate.
- Local/deployed SHA-256 values matched; root-only credential permissions, HTTPS and Nginx syntax were checked. Temporary diagnostic script removed locally and remotely after root-cause investigation.
- Independent `certbot renew --cert-name sensecms.com --dry-run --run-deploy-hooks` succeeded using the saved configuration: both auth hooks, both cleanup hooks and Nginx deployment hook completed successfully. Active certificate expiry remained 2026-12-05; timer active/enabled, canonical redirect preserved, no new Nginx service errors during verification.
